## 1. `useState` — estado de busca e categoria

Em `App.tsx`:

```ts
const [search, setSearch] = useState("");
const [selectedCategory, setSelectedCategory] = useState("");
```

O estado foi **lifted** para o `App` — o componente pai. Isso permite que tanto o `HomeHeader` (que exibe os controles) quanto o `ProductList` (que usa os valores para filtrar) compartilhem o mesmo estado sem precisar se comunicar diretamente entre si.

Dentro do `useProducts`, mais dois `useState` guardam o resultado da API:

```ts
const [products, setProducts] = useState<Product[]>([]);
const [loading, setLoading] = useState(false);
const [error, setError] = useState<string | null>(null);
```

---

## 2. `useEffect` — busca na API

Em `useProducts.ts`:

```ts
useEffect(() => {
  fetchProduct();
}, [fetchProduct]);
```

O `useEffect` sincroniza o componente com algo externo — nesse caso, a API. Ele roda após a montagem e chama `fetchProduct`, que seta `loading`, faz o fetch, trata erro no `catch` e garante `setLoading(false)` no `finally` independente do resultado.

A dependência é `[fetchProduct]` e não `[]` porque o `fetchProduct` é um `useCallback` — isso é importante para o passo 4.

---

## 3. `useMemo` — lista filtrada

Em `ProductList.tsx`:

```ts
const filtered = useMemo(
  () =>
    products.filter((product) => {
      const matchesSearch = product.productName.toLowerCase().includes(normalizedSearch);
      const matchesCategory = !normalizedCategory || product.category.toLowerCase() === normalizedCategory;
      return matchesSearch && matchesCategory;
    }),
  [products, normalizedSearch, normalizedCategory],
);
```

Sem `useMemo`, esse `.filter()` rodaria em todo re-render do `ProductList`, mesmo quando nada mudou. Com `useMemo`, o React só recalcula a lista quando `products`, `normalizedSearch` ou `normalizedCategory` mudam de fato.

Em `App.tsx` tem outro `useMemo` para as categorias do dropdown:

```ts
const categories = useMemo(() => {
  const unique = [...new Set(products.map((p) => p.category))];
  return [{ label: "Todas", value: "" }, ...unique.map(...)];
}, [products]);
```

Só recalcula quando `products` muda — ou seja, quando a API responde.

---

## 4. `useCallback` — referência estável da função

Em `App.tsx`:

```ts
const handleSearch = useCallback((value: string) => setSearch(value), []);
```

`ProductFilter` usa `memo`, o que significa que ele só re-renderiza se as props mudarem. Se `handleSearch` fosse uma função normal declarada no corpo do `App`, ela seria **recriada a cada render**, gerando uma nova referência — o que quebraria o `memo` do `ProductFilter`.

Com `useCallback` e dependências `[]`, a referência de `handleSearch` é criada uma única vez e permanece estável, deixando o `memo` funcionar de verdade.

O mesmo vale para `fetchProduct` em `useProducts`:

```ts
const fetchProduct = useCallback(async () => { ... }, []);
```

Ele é estável, então o `useEffect` que depende dele só roda uma vez — na montagem.
